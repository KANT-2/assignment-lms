# GitHub 제출물 자동 동기화 (`apps/github_sync`)

발표·설명용 정리 문서. 구현: `feat/github-sync-v2` 브랜치.

---

## 1. 왜 만들었나

- 지금 학생 제출물은 **LMS 서버 안에만** 있다. 수료하면 접근 못 하고, 서버가 죽으면 같이 사라진다.
- 학생 입장에서 "내가 부트캠프에서 한 과제들"이 **포트폴리오**로 남으면 좋다.
- → 학생이 LMS에 과제를 제출하면, **학생 본인 GitHub 계정**에도 똑같이 저장되게 한다.

## 2. 한 줄 요약

> 학생이 과제를 제출하면, 그 파일이 학생 본인의 GitHub 공개 저장소(`lms-assignments`)에 **자동으로 커밋**된다.
> 학생은 GitHub를 처음에 **한 번만 연결**하면, 그 뒤로는 아무것도 안 해도 된다.

## 3. 학생 입장에서 (제일 중요)

**딱 1번:** 대시보드에서 "GitHub 연결하기" 클릭 → GitHub에서 "허용" 버튼 클릭 → 끝.

**그 뒤로는 자동:**
- 과제 제출할 때마다 → 내 GitHub 저장소에 커밋
- 재제출하면 → 같은 파일 덮어쓰기 (새 커밋)
- 마감 후 → "최종 제출" 커밋 한 번 더
- 커밋은 **내 이름으로** 찍힘 → GitHub 잔디(초록칸) 채워짐

GitHub 비밀번호를 LMS에 입력하는 일은 **절대 없다** (뒤 6번 참고).

## 4. 동작 흐름 (그림으로 설명하기 좋은 순서)

```
[학생] 대시보드 → "GitHub 연결하기"
   ↓
[GitHub] "이 앱이 당신의 저장소에 접근해도 될까요?" → 학생이 "허용"
   ↓
[LMS] 학생을 대신해 커밋할 수 있는 "출입증(토큰)"을 받아서 암호화 저장
   ↓
─────────  여기까지가 최초 1회  ─────────
   ↓
[학생] 과제 제출 (평소처럼 파일 업로드)
   ↓
[LMS] 제출 저장되자마자 백그라운드에서:
        1. 학생 GitHub에 'lms-assignments' 저장소 있나 확인 (없으면 자동 생성)
        2. 그 저장소에 과제 파일 + 설명(README) 커밋
   ↓
[GitHub] github.com/학생아이디/lms-assignments 에 파일이 쌓임
```

## 5. 저장소에 어떻게 쌓이나

학생 계정에 저장소 하나(`lms-assignments`, 공개)가 생기고, 과제별 폴더로 정리된다:

```
lms-assignments/
└── ax-3차-프로젝트-평가/              ← 기수(프로젝트) 이름
    └── 07-1주차-리스트-다루기/         ← 과제 (번호-제목)
        ├── week1_solution.py          ← 학생이 낸 파일
        └── README.md                  ← 과제 설명 + 제출 설명 + 제출 시각 (자동 생성)
```

커밋 히스토리 예시:
```
[1주차 리스트 다루기] 최종 제출 · 2026-08-31 16:51   ← 마감 후
[1주차 리스트 다루기] 제출 · 2026-08-31 16:40         ← 재제출
[1주차 리스트 다루기] 제출 · 2026-08-31 14:20         ← 최초 제출
```

## 6. 핵심 설계 결정 (질문 나올 만한 것)

| 결정 | 이유 |
|---|---|
| **학교 저장소가 아니라 학생 개인 계정** | 학생이 수료 후에도 소유·활용 가능. 포트폴리오 목적. |
| **저장소는 public** | 포트폴리오로 보여주려면 공개여야. (학생이 나중에 private 전환 가능) |
| **커밋 작성자 = 학생 본인** | GitHub 잔디에 반영됨. 단, 이메일은 `아이디@users.noreply.github.com`로 넣어서 **개인 이메일은 노출 안 함**. |
| **비밀번호 대신 OAuth** | 학생이 GitHub 비번을 LMS에 안 넘김. github.com에서만 "허용"을 누르고, LMS는 제한된 출입증(토큰)만 받음. 언제든 학생이 GitHub 설정에서 취소 가능. |
| **팀 과제는 제외** | 팀 제출물은 "누구 것"인지 애매해서 개인 저장소에 넣기 곤란. 개인 과제만. |
| **키 없으면 완전히 꺼짐** | GitHub 설정이 안 돼 있으면 이 기능은 아예 동작 안 하고, 기존 제출 흐름엔 아무 영향 없음. |

## 7. 안 되는 것 / 한계

- **팀 과제**는 GitHub로 안 올라감.
- **GitHub 미연결 학생**은 LMS 제출은 정상, GitHub 저장만 건너뜀. 나중에 연결하면 그동안 낸 과제가 **소급해서** 올라감.
- 파일이 아주 크면(수십 MB+) GitHub이 거부할 수 있음 (일반 코드 파일은 문제없음).
- GitHub이 일시적으로 느리거나 장애면 그 순간 저장 실패 → **주기적 재시도 작업**이 나중에 다시 올림. (그동안 LMS 제출 자체는 항상 성공)

## 8. 기술 요약 (한 장)

- **OAuth 2.0**: 학생이 GitHub에서 앱을 승인 → LMS가 액세스 토큰 수령 → **암호화(Fernet)해서 DB 저장**
- **GitHub REST API (Contents API)**로 파일 커밋. 저장소 없으면 자동 생성.
- **트리거**: 제출 파일이 저장되는 순간(시그널) → 트랜잭션 커밋 후 즉시 push 시도
- **안전망**: `manage.py github_sync` 배치가 5분마다 — 실패분 재시도 + 마감 최종본 커밋 + 소급 push
- **상태 추적**: 제출물마다 `SubmissionPush`(대기/성공/실패/미연결) 기록 → 학생 화면에 "동기화됨 ✓" 표시
- `apps/core`(공유 모델)는 **미수정**. `Submission`과는 1:1 참조로만 연결.

## 9. 실제로 쓰려면 (배포 체크리스트)

1. GitHub에 **OAuth App 등록** (조직 계정 권장) — 콜백 URL을 서비스 도메인으로
2. 서버 `.env`에 값 3개: `GITHUB_OAUTH_CLIENT_ID`, `GITHUB_OAUTH_CLIENT_SECRET`, `GITHUB_TOKEN_ENC_KEY`
3. `python manage.py migrate`
4. **cron 등록**: `*/5 * * * * python manage.py github_sync` (재시도 + 마감 최종본)

## 10. 검증 상태

실제 GitHub 계정으로 전 과정 확인 완료:
연결 → 저장소 자동 생성(public) → 제출 push → 커밋 작성자 = 학생 → README 생성 → 재제출 덮어쓰기 → 마감 최종본 커밋.
자동 테스트 32개 통과.
