# 과제 제출 및 피드백 관리 시스템

**Product Requirements Document · v0.3**
2026-08-26 개정

| 버전 | 일자 | 주요 내용 |
|---|---|---|

### 1.1 배경 및 목적

현재 과제 공지, 제출, 피드백은 구두 안내와 Slack DM/채널을 통해 산발적으로 이루어지고 있어 누락과 혼선이 발생하고 있습니다. 본 시스템은 하나의 강의(과목)를 대상으로 과제 공지·제출·평가·피드백의 전 과정을 하나의 웹 시스템으로 통합해, 기존의 구두 공지와 Slack 커뮤니케이션을 완전히 대체하는 것을 목표로 합니다.

### 1.2 적용 범위

- 단일 강의(과목) 전용 시스템으로, 여러 강의·여러 튜터 간 공유는 지원하지 않습니다.
- 역할은 학생과 튜터 두 가지만 존재하며, 튜터는 해당 강의의 유일한 관리자입니다 (조교 없음).
- 팀 명단(팀 구성원 및 대표자 정보)은 별도의 팀 구성 관리 시스템(AX Evaluator)에서 관리되며, 본 시스템은 해당 데이터를 참조만 하고 직접 생성·수정하지 않습니다.

## 2. 사용자 및 역할

### 2.1 튜터 (교수)

해당 강의의 유일한 관리자로, 과제 등록·수정·삭제, 제출 현황 관리, 제출물 검토 및 평가(AI 1차 평가 확인 + 본인 평가 작성)를 담당합니다.

### 2.2 학생

과제 목록을 확인하고 제출하며, 본인이 제출한 과제와 그에 대한 AI/튜터 평가만 조회할 수 있습니다. 다른 학생의 제출물이나 평가는 열람할 수 없습니다.

## 3. 기능 개요

### 3.1 튜터 기능

- 과제 등록 / 수정 / 삭제
- 전체 과제 목록 조회 (제출 현황 요약 포함)
- 과제별 학생·팀 제출 현황 관리 (제출자/미제출자, 이름 검색, 상태 필터, 정렬)
- 제출물 검토 (파일 미리보기, 학생이 작성한 설명 확인)
- AI 1차 평가 생성 및 확인
- 튜터 평가 작성 (100점 만점 점수 + 텍스트 피드백)
- 온라인 강의 업로드 (계획 단계 — 3.3절 참고)

### 3.2 학생 기능

- 전체 과제 목록 확인 ("과제 확인" 화면, 진행중 + 마감 과제 모두 표시)
- 과제 제출 (파일 업로드 + 설명 작성)
- 재제출 (마감 전, 튜터 평가 등록 전까지)
- 본인 제출물 및 AI/튜터 평가 결과 확인
- 온라인 강의 시청 (계획 단계 — 3.3절 참고)

### 3.3 계획 단계 기능 (프로토타입 미제작)

아래 기능은 요구사항으로 확정되었으나 아직 목업이 제작되지 않았습니다. 난이도가 높지 않다고 판단되어 다른 기능들의 목업을 우선 완료한 뒤 후속으로 제작할 예정입니다.

- 온라인 강의 업로드 (튜터) — 강의 영상을 등록해 학생에게 공개
- 온라인 강의 시청 (학생) — 등록된 강의 목록을 확인하고 시청

## 4. 기능 요구사항 (Functional Requirements)

**FR-001 과제 등록 (튜터)**
튜터는 과제명, 설명, 제출 마감일시, 필수/선택 여부, 지각 제출 허용/불가, 개인/팀 과제 여부를 설정해 새 과제를 등록할 수 있다.

**FR-002 과제 수정 / 삭제 (튜터)**
튜터는 등록된 과제의 위 항목들을 수정하거나 과제를 삭제할 수 있다. 삭제는 실행취소(undo)를 지원한다.

**FR-003 과제 목록 조회 (학생)**
학생은 진행중인 과제와 마감된 과제를 모두 포함한 전체 과제 목록을 하나의 화면에서 확인하며, 과제별 본인의 제출 상태(미제출/제출완료/평가완료 등)를 함께 확인한다.

**FR-004 과제 제출 방식 (학생)**
학생은 파일 업로드(.py, .ipynb 권장, 그 외 형식도 첨부 가능) 방식으로 과제를 제출하며, 제출 시 과제에 대한 간단한 설명(텍스트)을 함께 작성한다.
＊ [수정] v0.1의 FR-005는 텍스트 또는 링크 제출만 허용하고 파일 업로드를 Out of Scope로 규정했으나, 실제 요구사항은 파일 업로드 방식이 맞는 것으로 확인되어 수정함.

**FR-005 제출 파일 자동 미리보기**
.py / .ipynb 파일은 업로드 즉시 코드/노트북 형태로 자동 렌더링되어 미리보기가 제공된다. 그 외 형식은 파일명과 크기만 표시된다.

**FR-006 재제출 (학생)**
학생은 제출 마감 전까지, 그리고 튜터 평가가 아직 등록되지 않은 경우에 한해 기존 제출물을 새 제출물로 덮어쓸 수 있다. 이전 제출 이력은 보관하지 않는다.

**FR-007 지각 제출 처리**
과제별로 지각 제출 허용 여부를 설정한다. 허용 시 마감 후 제출도 정상 제출과 동일하게 접수·집계되며, 불가로 설정된 경우 마감 후에는 제출 자체가 차단된다.

**FR-008 필수/선택 과제 라벨**
과제는 필수/선택 라벨을 가지며, 라벨을 제외한 마감·제출 방식·집계 방식은 동일하게 동작한다.

**FR-009 개인/팀 과제 구분**
과제는 개인 과제 또는 팀 과제로 등록되며, 팀 과제의 경우 사전 구성된 팀 명단을 기준으로 팀 대표 1인의 제출이 팀 전체의 제출로 처리된다.

**FR-010 제출 현황 대시보드 (튜터)**
튜터는 과제별로 제출률과 제출자/미제출자 명단을 확인한다. 개인 과제는 학생 단위, 팀 과제는 팀 단위로 표시되며, 이름 검색(팀원 이름 포함), 상태 필터, 정렬(이름순/최근 제출순/미제출 우선)을 지원한다.

**FR-011 제출물 검토 (튜터)**
튜터는 학생 또는 팀별 제출 파일 미리보기와 작성된 설명을 확인할 수 있으며, 목록으로 돌아가지 않고 이전/다음 이동으로 제출물들을 순차적으로 검토할 수 있다.

**FR-012 AI 1차 평가 (신규)**
튜터는 제출물 검토 화면에서 AI 평가 생성을 요청할 수 있다. 생성 시 100점 만점의 점수와 텍스트 코멘트가 함께 만들어지며, 튜터 평가 입력란보다 먼저 노출되어 튜터가 참고할 수 있다. 재생성도 지원한다.
＊ AI 평가는 Gemini 기반으로 구현할 계획이나, 현재 프로토타입은 실제 API 호출 없이 점수/코멘트를 시뮬레이션으로 생성한다. 실제 연동은 별도 백엔드 작업이 필요하다 (9장 참고).

**FR-013 튜터 평가 및 피드백**
튜터는 제출물에 대해 100점 만점 점수와 텍스트 피드백을 함께 작성해 저장한다. 저장 시 해당 제출물은 재제출이 제한되며(잠금), 튜터는 이후에도 저장된 점수·피드백 내용을 수정할 수 있다.
＊ [수정] v0.1의 BR-007은 "숫자 채점 없이 텍스트 피드백만 남긴다"고 규정했으나, 실제 요구사항은 AI 평가와 튜터 평가 모두 100점 만점의 숫자 채점을 포함하는 것이 맞는 것으로 확인되어 수정함.

**FR-014 평가 결과 조회 (학생)**
학생은 마감된 과제에 한해 본인의 제출물, AI 평가, 튜터 평가를 확인한다. 평가가 아직 등록되지 않은 경우 "평가 대기 중"으로 표시되며, 미제출로 마감된 과제는 "제출 기록 없음"으로 표시된다.

**FR-015 온라인 강의 업로드 (튜터, 계획 단계)**
튜터가 강의 영상을 시스템에 등록해 학생에게 공개한다.
＊ 요구사항으로 확정되었으나 프로토타입은 아직 제작되지 않음.

**FR-016 온라인 강의 시청 (학생, 계획 단계)**
학생이 등록된 강의 목록을 확인하고 시청한다.
＊ 요구사항으로 확정되었으나 프로토타입은 아직 제작되지 않음.

## 5. 비즈니스 규칙 (Business Rules)

**BR-001 단일 강의 운영**
본 시스템은 하나의 강의(과목)에 대해서만 운영되며, 튜터 1인이 유일한 관리자다 (조교 계정 없음).

**BR-002 본인 데이터만 조회**
학생은 본인의 제출물과 평가 결과만 조회할 수 있으며, 다른 학생의 제출물이나 평가는 열람할 수 없다.

**BR-003 필수/선택 동작 동일**
필수·선택 과제는 라벨만 다를 뿐 마감·제출 방식·집계 방식은 동일하게 동작한다.

**BR-004 지각 제출 시 라벨 처리**
지각 제출이 허용된 과제에서 마감 후 제출된 건은 정상 제출과 동일하게 처리되며, 학생 화면에는 별도의 "지각" 표시를 하지 않는다. 다만 튜터 화면에서는 "지각 제출" 배지로 구분해 표시한다.

**BR-005 팀 과제 제출/평가 단위**
팀 과제는 팀 대표자의 제출과 그에 대한 평가(AI/튜터)가 팀 전체에 동일하게 적용된다.

**BR-006 재제출 제한 조건**
재제출은 (1) 제출 마감 전이며 (2) 해당 제출물에 튜터 평가가 아직 등록되지 않은 경우에만 가능하다. 튜터 평가가 등록되는 즉시, 마감 여부와 무관하게 재제출이 제한된다.

**BR-007 채점 방식**
AI 평가와 튜터 평가는 모두 100점 만점의 숫자 점수와 텍스트 코멘트로 구성된다.
＊ [수정] v0.1의 "숫자 채점 없음, 텍스트 피드백만" 원칙을 폐기함.

**BR-008 AI 평가의 지위**
AI 평가는 참고용 1차 평가이며, 학생의 공식 평가 결과는 튜터가 작성한 점수와 피드백을 기준으로 한다.

**BR-009 AI 평가 실행 방식**
AI 평가는 튜터가 제출물 검토 화면에서 수동으로 생성을 트리거하는 방식으로 동작한다. 마감 시점에 자동으로 실행되거나 학생에게 자동으로 공개되는 절차는 현재 정의되어 있지 않다 (9장 열려있는 질문 참고).

## 6. 수용 기준 (Acceptance Criteria)

**AC-001 마감 전 제출 및 재제출**
과제 마감 전, 학생은 파일과 설명을 제출할 수 있고, 튜터 평가가 등록되기 전까지는 재제출(덮어쓰기)도 가능하다.

**AC-002 마감 후 · 지각 불가 과제**
지각 제출이 "불가"로 설정된 과제가 마감된 경우, 학생은 더 이상 제출할 수 없으며 제출 화면에는 마감 안내 배너가 표시된다. 미제출 상태로 마감된 과제를 조회하면 "제출 기록 없음"으로 표시된다.

**AC-003 마감 후 · 지각 허용 과제**
지각 제출이 "허용"으로 설정된 과제가 마감된 후에도, 아직 제출하지 않은 학생은 제출할 수 있으며 해당 제출 건은 튜터 화면에서 "지각 제출"로 표시된다.

**AC-004 평가 저장과 결과 공개**
튜터가 제출물에 점수와 피드백을 저장하면, 학생 화면에는 AI 평가와 튜터 평가가 함께 노출되고 해당 제출물은 재제출이 제한된다.

**AC-005 평가 대기 상태**
제출은 완료됐지만 튜터 평가가 아직 등록되지 않은 마감 과제는 학생 화면에 "평가 대기 중"으로 표시된다.

## 7. 화면 구성 (프로토타입 기준)

2026-08-26 기준으로 제작된 목업은 아래 3개 화면(Cowork Artifact)이며, 온라인 강의 관련 화면은 아직 제작되지 않았습니다.

- **학생 대시보드** — 달력, TODO, 우리 팀, 최근 공개 결과를 보여주는 학생용 홈 화면
- **학생 과제 확인** — 전체 과제 목록, 과제 제출/재제출, 마감된 과제의 제출물·AI 평가·튜터 평가 확인을 한 화면 안에서 처리 (실제 개발 시에는 별도 라우팅으로 분리될 수 있음)
- **튜터 과제 관리** — 과제 목록 및 등록/수정 모달, 과제별 학생·팀 제출 현황 명단, 제출물 검토 화면(AI 평가 생성 + 튜터 평가 작성)을 한 화면 안에서 처리

## 8. 범위 외 (Out of Scope)

- 다중 강의 / 다중 튜터 / 조교(TA) 계정 지원
- Slack 알림 연동
- 네이티브 모바일 앱
- 학생 간 제출물 상호 열람
- 텍스트/링크 제출 방식 (파일 업로드 방식으로 대체되어 더 이상 다루지 않음)
- 실제 Gemini API 연동 (현재는 시뮬레이션이며, 실제 연동은 별도 백엔드 작업)

## 9. 열려있는 질문 (Open Questions)

- 로그인 및 인증 방식을 어떻게 구현할 것인가.
- 지각 제출 허용 여부의 시스템 기본값을 어떻게 정할 것인가 (현재 프로토타입은 신규 과제 등록 시 "허용"을 기본값으로 두고 있으나, 정책으로 확정된 것은 아님).
- 과제를 삭제하면 기존 제출물·평가 데이터는 어떻게 처리할 것인가 (함께 삭제 / 보관 등).
- 학기 종료 후 제출물·평가 데이터의 보존 기간 정책.
- 뒤늦게 수강 등록한 학생이 이전 과제 목록·결과를 조회할 수 있어야 하는가.
- AI 평가를 마감 시점에 자동으로 실행할 것인가, 현재처럼 튜터가 수동으로 트리거하는 방식을 유지할 것인가.
- AI 평가와 튜터 평가의 학생 공개 시점을 분리할 것인가 (현재는 저장 즉시 학생에게 노출됨).
- 온라인 강의 업로드/시청 기능의 세부 요구사항 — 지원할 영상 형식, 재생 방식, 시청 여부 트래킹 필요 여부 등.
- 팀 대표(팀장) 지정 방식 — 외부 팀 구성 시스템(AX Evaluator)에 대표자 여부 필드 추가를 요청한 상태이며, 승인 여부에 따라 팀 대표 지정·검증 로직이 달라질 수 있음.
